# Инструкция для тестирования плагинов SpecStudioParser

## Подготовка

```
git pull origin feature/new-plugins
dotnet build SpecStudioParser.csproj -c Release
```

В nanoCAD: `_NETLOAD` → выбрать `SpecStudioParser.dll` из `bin\Release\net6.0\`

---

## 1. Attribute Export Pro (`ATTR_EXPORT_SHOW`)

### Тест 1.1: Сканирование блоков без атрибутов
**Что сделать:** Создать 2-3 простых блока (без атрибутов) на чертеже. Запустить `ATTR_EXPORT_SHOW`. Нажать «Сканировать».
**Что должно произойти:**
- В списке «Доступные атрибуты» появятся системные теги: `$BLOCK_NAME`, `$LAYER`, `$HANDLE`, `$X`, `$Y`, `$Z`, `$SCALE`, `$ROTATION`, `$EFFECTIVE_NAME`
- Статус: «Найдено блоков: N, уникальных имён: N»
- Все системные теги включены (чекбоксы отмечены)

### Тест 1.2: Блоки с атрибутами
**Что сделать:** Создать блок с 2-3 атрибутами (TAG1, TAG2, TAG3). Вставить 3 вхождения с разными значениями. Нажать «Сканировать».
**Что должно произойти:**
- В списке тегов появились TAG1, TAG2, TAG3 (помимо системных)
- Значения атрибутов корректные (не пустые)

### Тест 1.3: Блоки с Constant-атрибутами
**Что сделать:** Создать блок, у которого один атрибут отмечен как Constant (ATTDEF с Constant=yes). Вставить вхождение. Сканировать.
**Что должно произойти:**
- Constant-атрибут появляется в списке тегов
- Значение в таблице соответствует значению из определения блока

### Тест 1.4: Динамические блоки
**Что сделать:** Вставить динамический блок с параметрами (Distance1, Visibility1). Сканировать.
**Что должно произойти:**
- Появились теги `DYN.Distance1`, `DYN.Visibility1`
- Значения отражают текущее состояние

### Тест 1.5: Экспорт в CSV
**Что сделать:** Выбрать формат «CSV (.csv)». Снять галочки с нескольких тегов. Нажать «Экспорт». Выбрать путь.
**Что должно произойти:**
- Файл .csv создан
- В файле только выбранные колонки
- Кодировка UTF-8 (открывается в Excel без кракозябр)

### Тест 1.6: Экспорт в Excel (SpreadsheetML)
**Что сделать:** Выбрать формат «Excel (.xls)». Нажать «Экспорт».
**Что должно произойти:**
- Файл .xls создан
- Открывается в Excel с заголовками колонок (жирный шрифт, голубой фон)
- Данные корректные

### Тест 1.7: Фильтр по имени блока
**Что сделать:** Выбрать конкретный блок в выпадающем списке. Сканировать.
**Что должно произойти:**
- В данных только вхождения выбранного блока
- Остальные блоки исключены

## 2. Position Numbering Engine (`POS_NUM_SHOW`)

### Тест 2.1: Сканирование MLeader-выносок
**Что сделать:** Создать 3-4 мультывыноски (MLeader) с числами (1, 2, 3...) в ModelSpace. Запустить `POS_NUM_SHOW`. Нажать «Сканировать».
**Что должно произойти:**
- Таблица (DataGrid) заполнена строками: Handle, CurrentNumber, X, Y, Layer
- Количество строк = количеству выносок
- CurrentNumber содержит извлечённое число

### Тест 2.2: Сканирование блоков с атрибутом-позицией
**Что сделать:** Создать блок с атрибутом с тегом «POS». Вставить 3 вхождения. В поле «Тег» указать «POS». Сканировать.
**Что должно произойти:**
- В таблице 3 строки
- BlockName = имя блока, IsBlockAttribute = true

### Тест 2.3: Автонумерация (сверху вниз)
**Что сделать:** Расположить выноски вразнобой. Выбрать сортировку «Сверху вниз, слева направо». Нажать «Применить».
**Что должно произойти:**
- NewNumber заполнен: 1, 2, 3... начиная с верхней левой выноски
- На чертеже текст выносок обновлён новыми номерами
- Статус: «обновлено: N»

### Тест 2.4: Нумерация с префиксом
**Что сделать:** Указать префикс «П». StartNumber = 1. Применить.
**Что должно произойти:**
- NewNumber: «П 1», «П 2», «П 3»...
- Текст выносок на чертеже обновлён

### Тест 2.5: Перезапись vs пропуск
**Что сделать:** Расставить выноски с существующими номерами. Снять галочку «Перезаписывать». Применить.
**Что должно произойти:**
- Статус: «пропущено: N»
- Существующие номера не изменены

### Тест 2.6: Сортировка по слою
**Что сделать:** Расположить выноски на разных слоях. Выбрать «По слою». Применить.
**Что должно произойти:**
- Нумерация идёт группами по слоям (сначала все на слое A, потом B)

## 3. Dynamic Block Doctor (`BLOCK_DOCTOR_SHOW`)

### Тест 3.1: Диагностика обычных блоков
**Что сделать:** Создать 2-3 обычных (не динамических) блока. Запустить `BLOCK_DOCTOR_SHOW`. Нажать «Диагностика».
**Что должно произойти:**
- Карточки статистики: «Всего блоков: N», «Динамических: 0»
- Список блоков слева
- При выборе блока справа — пустой список проблем (или только «Тяжёлый блок» если >500 примитивов)

### Тест 3.2: Диагностика динамического блока
**Что сделать:** Открыть файл с динамическими блоками AutoCAD (или создать). Нажать «Диагностика».
**Что должно произойти:**
- «Динамических: N» — больше нуля
- При выборе блока — проблемы: «Динамический блок AutoCAD» (Warning), возможно «Параметр видимости» (Error), «Параметр растяжения» (Error)
- WorstSeverity отображается в списке

### Тест 3.3: Заморозка динамического блока
**Что сделать:** Выбрать динамический блок в списке. Нажать «Заморозить блок».
**Что должно произойти:**
- Статус: «Блок "X" заморожён → "X_FROZEN"»
- Автоматический пересканирование
- Заморожённый блок больше не отображается как динамический

### Тест 3.4: Прокси-объекты
**Что сделать:** Открыть файл из AutoCAD Architecture / MEP с прокси-объектами.
**Что должно произойти:**
- При диагностике: Warning «Прокси-объекты в блоке»

### Тест 3.5: Ассоциативная штриховка в блоке
**Что сделать:** Создать блок с ассоциативной штриховкой внутри. Провести диагностику.
**Что должно произойти:**
- Error «Ассоциативная штриховка в блоке»

## 4. Проверка UI / тем

### Тест 4.1: Цветовая схема
**Что проверить:** Все три окна используют цвета из AppTheme:
- Фон окна — светло-серый (#F7F7F5)
- Панели — белые (#FFFFFF)
- Заголовки — чёрные (#1F1F1F)
- Подсказки/статус — серые (#5F6368)
- Кнопки акцента — терракотовые (#B76E2B)

### Тест 4.2: Кнопки
**Что проверить:**
- «Сканировать» / «Диагностика» — оранжевые (accentButton)
- «Заморозить блок» — красная (dangerButton)
- Текст на кнопках читаемый

### Тест 4.3: Изменение размера
**Что проверить:** Окно можно растягивать. Содержимое не обрезается. Минимальные размеры соблюдаются.
